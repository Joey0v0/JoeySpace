# 多项任务草稿：方案与本轮范围

日期：2026-10-03。基线 main `1065ef6`。用户明确选择逐项确认、逐项回帖，以及未提交创建的项允许本人显式跳过；见 A54—A56。本轮先实现模型多项输出与后端逐项核验，持久化、RPC/HTTP、页面、逐项操作及跳过尚未实现，不将方案写成已交付能力。

## 1. 当前单项限制与业务目标

群讨论可以包含多项待办，例如“张三明天15:30修复缓存，李四明天下午整理文档”。模型应分别提取两项，后端分别解析真实负责人和时间依据；第二项时间未明确，不能妨碍第一项审查，也不能悄悄补一个小时。

三名子 agent 在主工作区只读核对后发现：

- [草稿生成](../rpc/agent/eino_task_draft.go)只生成一个对象；[准备流程](../rpc/agent/draft_preparer.go)在当前群授权后解析一项并保存。
- [存储](../rpc/agent/draft_store.go)虽有 `(run_id, item_index)`，查询/更新写死第 0 项；[确认](../rpc/agent/draft_confirm_store.go)把整个运行置为 creating/succeeded，Task 键固定 `agent-task-{run}-0`。
- [回帖记录](../rpc/agent/draft_reply_store.go)按 run 唯一；[IM 入口](../rpc/im/bot.proto)只有 run 身份，[发送记录](../rpc/im/bot_send_store.go)由 run 派生 `bot-task:<run>`。同一运行多张卡不能共用此键。
- [Gateway](../api/agent_draft.go)和[页面](../examples/chat.html)的版本、当前输入、状态和回帖均绑定一项；仅将模型对象换成数组，会造成误确认、整轮冻结或回帖冲突。

## 2. 已讨论的三个选择

| 选择 | 用户所选 | 备选及取舍 | 影响 |
| --- | --- | --- | --- |
| A54 确认单位 | 一次提取多项，本人逐项编辑、审查、确认和重试 | 一次确认全部操作少，但同步调用仍可部分成功，需要集合审查及逐项恢复；不能承诺跨 Task 服务全部回滚 | 每项独立版本、冻结、创建键与结果；某项创建不冻结其他项 |
| A55 群回帖 | 每成功一项回一张现有任务卡；每项可独立重试回帖 | 全部完成后一张汇总卡消息少，但须新卡片格式、汇总时机及部分完成展示 | 扩展 Agent/IM 的项身份与消息去重，保留独立 mTLS 和本人当前群权限 |
| A56 不需要的候选 | 未提交创建的项可由本人显式跳过，保留记录 | 暂留待确认改动少，但运行无法明确收尾 | 跳过须当前本人权限及项版本检查；creating/succeeded 禁止跳过；所有项已创建或已跳过才处理完 |

确认来源为用户对三项问题分别明确选择 A。不是把一般“继续”当作架构选型同意。上述新增流程尚未编码，当前单项没有跳过或多项确认能力。

## 3. 既定方案内的实施方向

沿用 A37 已有 `(run_id,item_index)`，保存后固定，不按显示排序重编号、不复用；独立 item ID 更便于新增/重排，但会增加旧身份映射，本版不增加插入、删除或重排。页面可显示顺序号，所有操作必须明确绑定后端稳定身份。A50 版本继续按项保护整份内容，不能用整轮版本冻结未处理项。

运行提供汇总进度，创建和回帖状态保持逐项表达。例如“2项已创建，1项结果不确定，1项待确认，1项已跳过”，不能用一个 HTTP 超时覆盖已成功项，也不能因回帖失败否认任务已创建。所有项已创建/跳过只表示候选处理完成，不能隐藏尚待回帖的项；回帖 accepted 仍仅表示 IM 已受理，不保证历史入库或成员送达。处理完成后，待定回帖仍可在本人先重读核对意图/状态后逐项显式重试，已受理项不重发。所有项跳过时显示“已处理，没有创建任务”，不伪装为任务创建成功。跳过不能用于取消已提交给 Task 的操作。

旧 item 0 的 Task 键、消息 ID 和结果逐字保留；扩展项使用稳定索引派生独立键，不拿 Task ID 假冒运行 ID。Agent 与 IM 仍各自拥有记录，不能用跨库写表绕过协议。确切新字段、迁移顺序和逐项消息 ID 需在接线批次形成共同契约。

旧单项接口不能把真正的多项运行默认为第 0 项，也不能确认全部；保护必须在 Agent 根据持久集合判断。新集合及逐项接口显式携带身份和项版本，页面校验返回身份。旧单项业务和请求指纹继续保留。以上是下一批兼容方向，本轮没有新增协议字段或发布多项入口。

## 4. 本轮可独立验证的最小前置

1. **模型输出。** 新增 `GenerateDrafts`，一次返回严格对象 `{"drafts":[...]}`，每项仍是现有七个必填字符串。首版最多 5 项，超限、零项或任意坏项明确拒绝，不截断、不返回局部集合；零项拒绝表示没有可返回的草稿，不是已创建任务。备选直接放开条数或截断，会扩大处理预算或悄悄丢待办；固定小上限便于审查与测试。输出字节上限沿单项限额乘以 5，不调整真实模型 Token/超时预算。真实模型可能因原输出预算生成不完整结果，届时拒绝而非部分成功，效果待真实模型验收。
2. **逐项核验。** 单项和多项共用原来源、负责人提及与真实成员解析、有限时间解释及完整字段校验。共享辅助方法只接收上游已授权的消息和可信范围，不成为免鉴权外部入口。所有项通过才返回准备结果；任何项不合法/读取成员失败则返回错误及空集合。准备过程不写 SQL、创建 Task 或发 IM 消息。
3. **集成与审查。** 主 agent 审查后端 worktree，确认原身份/当前群检查、旧指纹、同键先重放及单项保存顺序不变；运行适当 Go 回归并记录所有实际文件。Gateway/页面两名 agent 本轮只读审查，不制造无服务支撑的入口。

本批不接多项持久化与生成幂等，也不接集合读取、逐项确认/回帖/跳过；不能通过现有页面操作多项。下一批先发布共同协议与存储状态契约，再按后端、Gateway、页面的真实依赖并行。不得把 `GenerateDrafts` 成功返回候选当成实际 Task 创建或完整微服务链已可用。
