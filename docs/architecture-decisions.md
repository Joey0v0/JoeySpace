# 架构与技术选型记录

本文件用于审查已经落地或即将发生的关键选择。2026-09-29 首次补记历史决定：**“当前实现”只说明代码现在如此，不代表用户已经逐项确认**。后续每次遇到关键选型，先列备选方案并与用户讨论，再记录所选方案、理由、代价、确认状态和对应代码。实现范围与验证状态以 [项目计划](project-plan.md) 为准。

状态含义：**用户已定**＝用户明确选择的方向；**既有复用**＝旧项目已有，本次沿用；**当前实现、待复核**＝实现中采用，但尚未逐项讨论；**规划、未实现**＝尚不能算已交付；**待决定**＝受影响代码暂停。

当前已实现：Eino 提取必填负责人称呼，Agent 核对授权文本中的原文证据，以原 Token 调 User；完整唯一候选预存 ID，零个/多个/截断保留状态，异常或权限失败不降级。Agent 草稿表新增两个标量列与 016 迁移；旧行默认空值保留旧意图，原请求键重放不重新生成或解析。GET RPC 追加字段。含称呼草稿在完整审查契约接入前拒绝旧确认，不冻结也不调用 Task；本人选择、Gateway/页面及完整确认审查尚未实现。表中已区分上一 User 子步骤与本轮 Agent 实施范围；阶段 6 未全完成。

本轮普通实现备选、理由与代价：

- 后端在模型后固定调用解析，而非让模型直接给 ID 或自由选择解析工具：沿用现有单项链、便于验证授权，首版不含自动澄清。
- 既有草稿加两列，而非独立新表/JSON 成员目录：仍由 Agent 保存提取与选择状态，User 拥有真实成员资料；需要迁移，只保存原称呼/状态/唯一 ID，不保存长期候选名单，后续选择重查当前成员。
- 模型称呼字段必填，而非遗漏自动认为无人负责：违反契约会拒绝生成；旧持久数据仍兼容。原文包含检查阻止凭空名字，但不证明模型正确理解分工。
- 同时校验 User 候选顺序、唯一 ID、字面匹配及上限，而非直接用第一条：异常响应拒绝；代价是异常或旧 User 无新方法时请求失败。
- 在负责人审查接口完成前拦截旧确认，而非让旧客户端忽略新字段后自动指派：保持本人确认的既定规则；代价是含称呼草稿本轮暂不能创建。扩大旧值比较与增加版本列尚未选择/实现，不提前修改其并发策略。

Agent/进程/Gateway 定向、全量 Go 和 Linux Agent 编译通过。本机 TCP 组合测试使用实际 Agent 生产构造、Eino 链及 SQL 适配，User/IM/Task 业务、模型和数据为替身；重放模型/解析各调用一次，旧确认 Task 零调用。真实迁移、MySQL、方舟、浏览器、容器和云端未验收。[27 文件与全部验证范围](agent-assignee-design.md#8-agent-提取解析与持久化审查2026-10-03)；[计划](project-plan.md#9-当前进度与下一步)。
