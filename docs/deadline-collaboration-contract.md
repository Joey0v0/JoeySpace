# 截止时间人工编辑：共同实施契约

日期：2026-10-03。用户明确选择 A51/A52/A53 的 A：首版统一 Asia/Shanghai，模型提取原文由 Go 有限解释，本人指令参考由首次页面提交固定。本批只完成其中的人工编辑/审查基础，不实现模型时间提取、解析状态、生成参考字段或新增迁移。原 UTC 列、A50 版本及 Task 幂等链复用。

## RPC 与存储

- `EditTaskDraftDeadline(run_id, optional due_at_unix_ms, expected_revision)`：原 Token，字段必须存在；合法整数范围 0..253402300799999，0 明确清除。原发起人、当前团队群权限，只允许 waiting_confirmation。
- 短事务锁定完整草稿，核对身份/范围/内容/版本；只更新 due_at_unix_ms，保持负责人及文字、来源等其余字段；实际变化版本加一，相同值 no-op，版本耗尽拒绝变化。没有新的列或迁移。网络授权不放在事务内。
- Confirm 追加 optional `expected_due_at_unix_ms = 6`，保留原字段号。非法范围拒绝；存在时编排与冻结事务均比较当前值，错误返回 Aborted。非零截止时间缺审查值返回 FailedPrecondition；零值旧草稿兼容缺失，新页面始终发送包括 0。该规则也适用于 creating/succeeded 的显式重试，不重算日期或改写原时间。
- 与已有负责人审查一起保护完整冻结内容。冻结、结果保存和回帖不加内容版本；Task 固定键/冻结时间保持，当前发起人群资格继续重查。

## Gateway

新增 `PUT /api/v1/agent/runs/:run_id/draft/deadline`，15 秒预算，正文上限 1 KiB：

```json
{"due_at_unix_ms":1791097200000,"expected_revision":"2"}
```

时间必须显式 JSON 整数，拒绝缺失/null/字符串/小数/负值/越界/额外字段；版本正十进制字符串。原 Token 转发，不能收用户/团队范围。成功返回完整待确认草稿，时间等于请求，版本只能原值或安全加一；异常结果 502。409 对应过时/冻结等冲突，其他错误沿用既有映射。

Confirm 正文允许 optional `expected_due_at_unix_ms` 数字，严格保留缺失和 0，成功结果有提供时核对一致。共享输出 GET/所有编辑/确认/回帖都检查截止时间范围，HTTP 仍数字（上限小于 JS 安全整数）。不在 Gateway 决定权限或计算日期。

## 原生页面

- 草稿展示已保存 UTC 时间的 Asia/Shanghai 日期时间及明确时区标识，0 显示未设置。旧响应缺时间字段兼容只读，不能把缺失默认为已审查零；现有标准 Gateway 始终输出数字。
- 增加专用 datetime-local 输入，按 Asia/Shanghai 而非设备本地时区转换；空输入代表明确清除但必须点击保存，不自动写入。显示/转换必须验证真实日期、范围及精度，不能偷偷截断旧值的秒/毫秒；未编辑的旧时间仍能审查确认或 no-op 保存。
- 已保存时间与编辑输入分开，待保存时间/文字/负责人阻止确认。保存返回完整范围、未变字段、合理版本后更新快照；冲突或不确定保留输入并要求 Load。所有草稿操作与新时间操作互斥；Token/团队群/run/epoch 改变后的旧响应不得恢复写入。
- 新确认总是携带快照中的 expected_due_at_unix_ms，包括 0；确认和回帖结果不能更改冻结时间。创建中/成功仅显示不可编辑原时间。
- 使用现有浏览器 Date/Intl 和 Node 测试，不加前端依赖；人工 Task 表单的原浏览器本地时间规则保持。Asia/Shanghai 的历史夏令时重复/不存在时间应拒绝或要求更明确输入，不假称永久 UTC+08:00。

## 并行范围与步骤

共同协议/生成代码和文档由主 agent 独占。后端最多三小步：时间写入；确认审查；有意义回归。Gateway最多两步：专用入口/共享验证；确认字段/测试。页面最多两步：显示与输入；保存/审查/回归。主 agent 契约1步、集成1步，整个业务实施批次最多九步，不将只读设计计为各 agent 可各做九步。

- 后端：rpc/agent 非生成实现/测试，必要 cmd/agent 替身适配，禁止依赖/迁移/协议改动。
- Gateway：api Go 文件，禁止修改主 agent 保留的 api/deadline_flow_integration_test.go。
- 页面：仅 examples/chat.html、examples/chat.test.cjs。
- 主 agent：上述共享文件、跨层组合测试、完整交付记录。每个执行 agent 明确工作目录和允许文件后开始；遇到新关键选择先报告，不擅自扩展自动解析。

同一新协议提交为共同基线。子 agent 不自行提交/合并/推送，主 agent 审查后提交，按后端→Gateway→页面集成；本地通过不等于真实 MySQL、浏览器、模型或云部署验收。时间提取/持久依据和 A53 生成请求接线属于下一批，不能将本批人工编辑标为完整 AI 时间识别。
