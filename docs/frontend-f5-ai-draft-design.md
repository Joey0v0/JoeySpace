# F5 AI 草稿前端方案（用户已确认）

日期：2026-10-10
基线：F4 本地集成提交 `6a4aaaf`，分支 `codex/frontend-f5-ai-draft`。本文只确定 F5 产品与接口方案，不表示 Vue 已接入 AI，也不替代 F6 的真实环境验收。

## 1. 要完成的事

F5 让团队成员在群聊里向 AI 提问，或发送一条明确的 `@AI 整理任务 …` 指令；发起人从这条已保存的消息查看处理状态，审查 1—5 项候选任务，逐项保存调整、确认创建或跳过。任务创建成功后，群内机器人回帖作为独立结果显示和重试。

F5 延续“先看讨论，再处理本人事项”的聊天优先结构。AI 入口在当前团队群，草稿是暂时打开的右侧面板；不添加第三个常驻模块、独立 AI 私聊、全局运行中心或批量自动确认。问答结果只在本次面板中显示，不伪装为已保存的聊天记录。

## 3. 已有能力与本阶段缺口

| 需求 | 当前已有 | F5 要接入的前端能力 |
| --- | --- | --- |
| 当前群问答 | `POST /api/v1/teams/{team}/groups/{group}/ask`，同步返回回答；Agent 复核当前群资格 | 群顶部入口、提问/等待/失败/结果展示，离群后清除回答 |
| 指令处理状态 | 已保存本人 `@AI` 消息的 `GET .../agent-triggers/{message}`；状态为 `queued/running/exhausted/completed`，完成才给 `run_id` | 原消息入口、只对当前打开的指令轮询、可手动刷新 |
| 多项草稿 | `GET /api/v1/agent/runs/{run}/drafts` 和 `.../{item_index}`，1—5 项，Agent 按发起人和当前群资格读取 | 严格解码、逐项摘要与展开审查、深链接刷新后重读 |
| 修改与决策 | 分开的文字/负责人/期限 PUT、确认/跳过 POST，均有保存版本约束 | 本人明确保存和审查，冲突时保留本地输入并重读，不批量确认 |
| 群内回帖 | 逐项 `.../reply/retry`，任务创建与回帖状态独立 | 明确标出“任务已创建，回帖待处理”；只重试原项回帖 |

这些接口已存在于 `api/main.go`、`rpc/agent/agent.proto` 和原生演示页。Vue 目前没有 Agent API 或状态模块；旧演示页的 DOM 脚本只作为契约参考，F5 使用 TypeScript 状态模型实现。同步 `task-draft-collections` 生成入口保留兼容，但 F5 主流程使用现有后台 `@AI` 指令：当前同步 Gateway 超时为 22 秒，而草稿模型可能执行更久；把同步生成为并列入口会带来额外的不确定结果恢复界面。现有 Vue API 客户端统一 15 秒中止请求，短于 Gateway 问答 22 秒、确认 20 秒及回帖重试 19 秒的上限；F5 需要针对这些操作延长客户端等待，并保留写入结果不明后的重读流程。

## 4. 页面与主流程

```text
团队群聊天
  ├─ 顶部「AI 助手」→ 右侧面板提问 → 当前群回答（本次可见）
  ├─ 面板「整理讨论事项」→ 在聊天输入框填入 @AI 整理任务 … → 本人检查后发送
  └─ 本人已保存的 @AI 指令消息「查看处理」
       → 等待/处理中/失败/已生成 → 右侧面板逐项审查
       → 保存文字/负责人/期限 → 确认创建或跳过
       → 已创建任务链接 + 独立群回帖状态
```

- 群顶部按钮只在已加入、当前有权阅读的团队群出现。右侧面板先沿用 F4 的 420px 桌面侧栏及窄屏覆盖模式；1280px 下聊天仍可阅读。面板内部滚动，群目录与聊天位置不被替换；实际宽度经浏览器检查再微调。
- 问答视图显示当前团队群名称、问题输入、提交与回答。回答只在当前面板保存；关闭、换群、换账号后清除。503/504 表示本次回答没有得到确认，可由用户重新提问；不会自动发群消息或创建任务。
- “整理讨论事项”只把明确的 `@AI 整理任务 ` 前缀写入当前群输入框并聚焦，用户补充要求后亲自发送。发送继续遵守 F3 的 WebSocket 受理与历史持久化区别；未进入历史的临时气泡不显示草稿入口。
- 仅本人、普通用户发送且有正持久消息 ID 的候选指令旁显示“查看 AI 处理”。入口须有明确的 `sender_type` 为普通用户、`initiator_id` 为 `"0"`、`content_type` 为文本，并完整匹配允许前导空白的 `@AI 整理任务 <要求>` 格式及 2000 个 Unicode 码点限制；缺字段时隐藏入口，实施前核实历史接口稳定回传这些字段。页面匹配只决定入口可见，**是否真有触发记录由 Agent 状态接口决定**；不会从正文推断运行 ID 或结果。别人的指令和机器人回帖不提供本人草稿入口。
- 打开原指令时，浏览器地址保留团队、群和消息 ID，例如 `/messages/teams/{team}/groups/{group}?ai_message_id={message}`。刷新后重新按原消息查询状态，完成后才按返回的 `run_id` 读取草稿，并核对集合返回的运行 ID、团队与群范围；不接受地址栏单独提供的 run ID 作为权限依据。草稿项的 `source_message_id` 是讨论依据，可能与触发指令消息不同，单独按当前群权限提供来源链接。原消息入口由已有群历史提供，旧消息可通过已有历史分页找到；不另建全局运行目录。
- 关闭面板、切换群/账号或失去群资格时，取消轮询并使在途回包失效。群历史、任务状态和草稿数据各按其服务端权限核验；403/404 清除面板内私有数据。

## 5. 指令与草稿状态

| 服务端状态 | 页面文字与动作 |
| --- | --- |
| `queued` / `running` | “等待处理”/“正在整理”；只轮询当前打开的本人指令，允许手动刷新，不给假进度条 |
| `exhausted` | “本次未能生成草稿”；解释可重新发送一条新指令，但旧指令没有后台重试按钮 |
| `completed` | 使用响应中的正 `run_id` 读取 1—5 项草稿；加载失败可重试读取，不回到模型生成 |
| 草稿项 `waiting_confirmation` | 展示来源、标题说明、负责人及期限依据；可编辑、保存、确认或跳过 |
| `creating` | 任务创建结果待核对；冻结编辑和跳过，先重读同一项，确有必要才显式重试同一项确认 |
| `succeeded` | 展示任务 ID/任务详情入口；回帖状态单独显示 |
| `skipped` | 标示“已跳过，不创建任务或回帖”，不可继续编辑 |

状态轮询建议打开时每 5 秒一次，持续 2 分钟后降低至每 15 秒，最多 10 分钟后停止并保留“刷新状态”；后台真实执行仍继续，面板不会凭本地计时宣布失败。只允许一个在途请求；路由/身份世代变化废弃旧响应。这个间隔是实现建议，浏览器测试再核对负载和等待体验。

草稿列表默认显示一项摘要，最多一项展开编辑。页首显示“待审查 / 已创建 / 已跳过”准确计数；部分成功时逐项保留结果，不把整批标为失败。来源、模型提取的原始负责人称呼、解析状态及期限原文/来源/时区/原解析候选与当前保存值分开呈现，帮助用户发现误提取。若期限或负责人为 `needs_input/not_found/ambiguous/truncated`，确认按钮保持不可用，必须明确选择当前团队成员、未指派、具体时间或不设期限并保存。

## 6. 保存、确认与失败恢复

1. 标题/说明、负责人、期限分别调用已有 PUT；每次发送当前 `revision`，保存成功后以服务端返回的整项替换本地保存态。负责人从现有当前团队成员目录选，不能手输 ID；截止时间沿用 F4 的 Asia/Shanghai 输入与 UTC 毫秒转换。
2. 本地未保存输入明确标记。切换草稿项、关闭面板或改变群时提示先保存或放弃，避免悄悄丢失编辑。保存操作与任务创建分开；修改了任一字段时禁用确认/跳过。
3. 确认请求提交已读取的标题、说明、`revision`、负责人 ID、截止时间和期限解决状态。服务端再次核对本人、群资格、版本与当前成员；页面不以按钮可用代替服务端授权。一次只确认一项，不自动推进到下一项。
4. 编辑/确认/跳过遇到 409 或结果不明的 503/504，先读取同一项的持久状态；保留用户未保存输入供对照，但不自动覆盖新的服务端版本。`creating` 的再次确认沿用原 run/item 的持久创建键，不生成第二项任务。跳过结果不明也先重读，避免重复假设。
5. 回帖状态 `disabled/not_started/pending/accepted/unknown` 与任务状态分开。只有任务已创建且重读确认回帖仍为 `not_started` 或 `pending` 时显示逐项重试；`unknown` 只提示核对，不自动重发。`accepted` 文案为“IM 已受理”，不宣称成员已送达或已读；回帖重试不再创建任务。
6. 已创建任务链接打开 F4 任务详情；从群消息进入草稿后，浏览器返回应回到原聊天上下文。后台处理失败、服务不可用、草稿权限撤销、冲突、输入不足分别给出可操作提示，绝不把失败变成空草稿或擅自确认。

API 客户端只为 F5 操作增加可配置等待：问答至少覆盖 Gateway 22 秒、确认至少覆盖 20 秒、回帖重试至少覆盖 19 秒，并给网络传输留少量余量；其他已验证请求保持原 15 秒默认值。读取和编辑按实际 Gateway 上限设置，不用全局放大超时。客户端中止或收到 503/504 时，任何已发送的写请求都视为“结果待核对”：先按原 run/item 重读，只有确认未生效且允许重试时才再次提交。面板加载与错误使用可读状态提示；打开后聚焦面板标题或关闭按钮，关闭后恢复触发处焦点，逐项操作有明确按钮名称。

## 7. 接口边界和预计代码范围

| 调用链 | 接口与数据约束 |
| --- | --- |
| Vue → Gateway → Agent Ask | 当前 `team_id/group_id` + 1—2000 字问题，返回纯回答；不写聊天历史 |
| Vue → Gateway → Agent Trigger | 原消息 `team_id/group_id/message_id`，只接受四个状态；仅 `completed` 有正 `run_id` |
| Vue → Gateway → Agent Collection | 用状态返回的 `run_id` 读取当前群 1—5 项；`run_id/task_id/revision/source_message_id` 均保持十进制字符串，`item_index` 是 0—4 的数字，期限毫秒值在现有安全范围内 |
| Vue → Gateway → Agent Item | 文字/负责人/期限的 PUT、确认/跳过/回帖的 POST；写后使用权威返回项，失败时重读同一项 |

预计主要修改 `frontend/src/messages/ConversationView.vue`、`MessagesPage.vue`、`frontend/src/api/client.ts`，新增 `frontend/src/agent/` 的类型化解码、状态控制和面板组件，并少量扩展 `frontend/src/style.css` 与相应测试。现有群路由已支持查询参数，不计划修改 `frontend/src/router.ts`。现有 Gateway/Agent RPC、数据库表和协议先复用；若实施时发现契约缺口，先给出具体备选和影响再动后端。旧原生演示页保持兼容，不把其脚本嵌入 Vue。

## 8. 审查重点、验收与边界

- **已确认的方案：** 沿用已确认的 A64 原指令入口；群顶部只承载问答与“填入整理指令”，不新增同步生成按钮或全局运行列表。草稿使用右侧临时面板、逐项人工确认，完全复用现有多项 Agent 契约。
- **本地验收：** 两账号中只有原发起人且仍具群资格者可看状态/草稿；历史元数据缺失时不显示入口；大整数 ID、1—5 项、部分成功、多人同项版本冲突、负责人重名与期限不明确、创建/回帖双重不确定结果、Gateway 慢响应与客户端超时后重读、身份/群切换旧回包、输入法 Enter 与键盘焦点均有针对性验证。浏览器替身在 1280/1440/1920 宽度检查面板不挤掉聊天。
- **真实环境边界：** F5 本地接线后仍需 F6 双账号、真实 MySQL/Kafka/Redis/mTLS、模型长等待、浏览器与静态页/API/WS 反代整链验收。已知云端模型曾间歇 503/504 和预算耗尽，页面必须如实表达等待与失败；不把旧演示页的一次通过当成新 Vue 已通过。

用户已审查方案和[八任务实施计划](superpowers/plans/2026-10-10-frontend-f5-ai-draft.md)并要求继续；实施按项目约定逐步开发。关键取舍的确认状态见[架构记录](architecture-decisions.md)。
