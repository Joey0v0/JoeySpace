## 目标与边界

F6 的目标是确认 F1—F5 的 **Vue 正式页面** 能通过一个稳定入口，在真实 JoeySpace 服务上完成“双账号登录 → 看讨论与未读 → 处理任务和通知 → 问答与逐项审查 AI 草稿”的使用流程。验收要分清浏览器看到的结果、服务端持久事实和仍待验证的失败场景；本地替身通过不能替代真实链路。

保持聊天优先、桌面浏览器优先，不新增产品模块或重写后端业务。若真实联调发现缺陷，按一个问题一个小步补回归并修复；新增服务边界、权限或数据归属选择仍先讨论。部署操作和外部环境写入要以用户审查过的具体配置与命令为准。

现状依据：[F3 审查](frontend-f3-second-review.md)、[F4 审查](frontend-f4-review.md)、[F5 审查](frontend-f5-review.md)。F5 分支包含前述前端阶段的集成代码，当前 `npm test` 132/132、类型检查与生产构建通过。`frontend/vite.config.ts` 仅配置开发代理；现有 Compose 暴露 Gateway `8082`、IM WS `8081`，正式 Vue 静态站点和同源代理尚未配置。`deploy/verify-cloud-browser.cjs` 操作的是旧 `/demo/chat` 页面，不能据此宣布 Vue 验收通过。

## 已确认的正式页面入口

用户确认采用一个轻量 Nginx 容器托管 Vue 构建产物并做同源转发。它不持有聊天、任务或 AI 数据，不执行业务鉴权；Bearer、当前团队资格、写入版本及重试规则仍由现有 Go 服务决定。

| 浏览器路径 | Nginx 处理 | 权威服务与核对点 |
| --- | --- | --- |
| `/`、`/messages/**`、`/tasks/**` | 返回构建后的 Vue 页面；深链刷新回退到 `index.html` | Vue Router 继续按当前登录身份重新取数据 |
| `/assets/**` | 提供带内容哈希的构建文件 | 更新后不会混用旧页面与新脚本 |
| `/api/v1/**` | 原路径转发到 `api-gateway:8082` | Gateway/各 RPC 继续核权；HTTP 错误码与 JSON 原样返回 |
| `/ws-ticket` | 原路径转发到 `im-ws:8081` | 现有一次性票据接口 |
| `/ws` | 保留 Upgrade/Connection 与必要转发头到 `im-ws:8081` | 现有 WS Origin 白名单、一次性票据、实时帧 |

拟以单独 Compose 覆盖文件加入前端服务，避免改变基础服务的容器归属；通过锁定的 npm 依赖构建 `dist`，运行镜像只包含 Nginx 和静态文件。验收入口先绑定服务器回环地址的独立端口，通过已有 SSH 隧道在开发者电脑访问，避免把未经验证的站点直接开放公网。WebSocket `Origin` 白名单加入该实际页面 Origin，同时保留已使用的演示页 Origin；具体地址、端口和任何公网/TLS 入口在实施计划中按环境核对。静态页面路由回退不能吞掉 API/WS 的 404、403 或连接失败；`index.html` 不做长期缓存，哈希资源可以缓存。

备选方案：让 Gateway 同时提供静态页并承担 WS 代理，会扩大 Go 入口代码与回归范围；让浏览器分别访问 Vite、8082、8081，会增加跨源认证与 Origin 配置，且开发服务器不适合作为正式站点。选择 Nginx 的代价是一份小型容器/配置、构建和运维入口，换来单一浏览器来源和较小业务代码改动。此项决定另记于[架构记录](architecture-decisions.md)。

## 验收顺序与通过条件

1. **冻结版本和环境。** 以 F5 集成提交建立 F6 分支，记录 Git SHA、Compose 覆盖、迁移版本和服务镜像标签；先核对云端当前代码、私有配置与已有数据卷。只在准备好回退方法后同步。F3 的 036 提及关系表、F4 的 037 任务索引等迁移按依赖顺序检查，不能从新库 `init.sql` 推断旧数据卷已升级。
2. **静态与路由。** 构建后的 Vue 首页、群聊/任务深链和刷新均返回正确页面；缺失资源或 API 错误不返回 Vue HTML。浏览器通过同源路径取得 Gateway JSON、WS 票据并完成 WS 升级；断线后依靠现有重连和权威补查恢复。
3. **双账号消息。** 用一次性账号/团队/群验证登录身份、会话目录、群聊与私聊收发、历史分页、跨会话未读、普通成员 `@我`、显式已读、离线补拉；检查另一账号收到的消息与持久历史一致，阅读不会自动标已读。
4. **任务与通知。** 从讨论消息创建任务，另一个账号在“我的任务”查看本人范围、处理三态、回看来源；跨团队通知、实时刷新提示和显式已读均与权威列表一致。超时或冲突时核对最终任务事实，不只看按钮文案。
5. **AI 草稿。** 在真实团队群 Ask；本人发送 `@AI 整理任务`，从已保存原消息打开状态。对 1—5 项草稿逐项编辑、补正含糊负责人/期限、确认或跳过；核对任务只创建一次，机器人回帖状态与在线/历史消息分开记录。模型若返回少于五项，只验实际返回项，不伪造五项成功。模型 503/504、预算耗尽或生成失败单独记为失败结果，不据一次成功宣称稳定。
6. **权限与恢复。** 第二账号不能查看他人 AI 草稿；离队/撤权后重查群历史、任务、通知和草稿均不能保留旧私有内容。覆盖切群、切账号、刷新深链、服务短暂停顿或网络中断后的旧回包隔离与重读。破坏性较高的 Push 停机测试沿用既有专项脚本，在明确的维护窗口单独执行，不与浏览器验收并行。
7. **浏览器体验。** 重点在 1280×720、1440×900、1920×1080 检查聊天、任务和 AI 面板的可读性、横向溢出与焦点返回；用真实键盘核对输入法 Enter、Tab 可达性与关闭面板。手机全量适配不纳入 F6。

每项记录：环境和版本、测试账号代号、步骤、预期、实际、请求/日志或截图证据、结论 `PASS`/`FAIL`/`BLOCKED`/`NOT RUN`。遇到 `FAIL`，先复现与定位，再决定是否需要代码修复；修复后只重跑受影响链和必要回归，不用无关测试数量代替真实验证。`BLOCKED` 写明缺少的外部条件，如服务不可达或模型额度，而非标为产品通过。

## 执行与交付约束

先完成可本地复核的 Nginx 配置、Docker 构建、Compose 静态检查及页面代理测试，再提交具体部署差异供用户审查。用户确认后才同步云端、执行迁移/重建和真实环境写入。真实验收使用一次性数据，不清理现有业务记录，不把密码、Token、SSH 私钥或私有 `.env` 写入仓库或报告。已有旧演示页及其验收脚本继续保留，用作后端诊断；F6 新证据明确指向 Vue 正式页。

阶段交付包括：正式前端入口配置与说明、针对 Vue 的真实浏览器验收脚本或可重复清单、逐项证据索引、发现问题的定向修复，以及一份 F6 审查报告。报告明确 `main` 合并、推送和云端部署是否实际发生，不以本地构建或替身测试推断。完成前需要用户审查本设计和后续实施计划。
