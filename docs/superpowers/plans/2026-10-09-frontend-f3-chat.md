# JoeySpace F3 真实聊天实施计划（待审查）

**目标：**在 F2 真实导航上完成有权会话的消息阅读、发送、显式已读与断线恢复，再交付权威跨会话未读和 `@我`。设计与选型见 [F3 设计](../../frontend-f3-chat-design.md)。本文是实施计划，不表示产品代码已经修改。

**共同基线：**`codex/frontend-f3-chat` 从 F2 `37c72cd` 建立；主 agent 负责共享协议/生成代码、迁移、依赖、Gateway、文档及集成。确认 F09—F11 后，最多三个执行 agent 从同一共同提交在独立 worktree/分支工作，各自绝对目录和允许文件先记入协作计划，不得合 main。本批最多九个小步；每步开工前向用户说明目标、理由、问题、预计文件，集中汇报实际文件、调用链、测试与未验收。用户可提前审查。

## 批次一：可运行讨论链路（八步）

1. **固定 F09 与既有消息契约。**主 agent 在 `docs/architecture-decisions.md`、本设计、`internal/ws/` 相关协议测试中固定一次性票据、来源限制、错误状态和旧入口兼容；若需新 HTTP 路由与 Redis 操作，由主 agent 定接口及共同提交。验证票据单次消费/过期/跨身份/Origin；不改聊天消息实体。
2. **有权历史读取模型。**Vue 执行 agent 仅修改 `frontend/src/messages/` 及其测试，接群/私聊现有 Gateway 历史、游标和消息类型；当前会话、身份切换或 403 使旧回包失效。验证大 ID、重复页、失败重试和滚动位置。
3. **当前会话未读与显式确认。**Vue agent 接两类现有 unread/read 路由，只提交已加载且可读的具体 ID，每次最多 100；成功后重查计数，超时显示待核对。验证自己消息、机器人、重复提交、撤权与 100 条边界。
4. **WS 票据与代理。**主 agent 实现获票/消费、Origin 限制、`frontend/vite.config.ts` 的 `/ws` 代理；Vue agent 只接客户端连接管理。验证浏览器 URL 不含长寿 JWT、断开/重连/退出销毁、旧演示页兼容与配置错误。需要的后端接口与测试由主 agent 保有。
5. **纯文本发送与结果核对。**Vue agent 接 WS chat/ack/错误；单飞发送，`msg_id` 恒定，IME/Shift+Enter 正确，ACK 与持久历史分状态；断线保留草稿和待核对项。验证 ACK 丢失、历史延迟与 Redis 五分钟界限。
6. **实时、离线与补拉。**Vue agent 按 `msg_id` 合并实时/离线帧，按持久 ID 分页；重连查询当前会话历史和未读，离线 ACK 只管投递。主 agent 核对现有离线无分页接口的积压边界，必要时单独提出补页契约。验证重复、错会话、错身份、离线查询失败。
7. **视觉与交互整合。**Vue agent 保持三栏、桌面 1280/1440/1920、键盘焦点、底部滚动规则、新消息提示和会话草稿；不新增看板/附件等范围。运行前端测试、类型检查、构建和本地浏览器检查。
8. **主 agent 集成审查。**逐提交核对权限、业务状态及变更文件；运行相关实际 HTTP/WS/TCP 组合、全仓 Go 与前端检查；记录未验证真实依赖。只提交 F3 分支供用户审查，不自动合 main、推送或部署。

每步实际文件在开工前以共同接口和允许目录进一步收窄；计划中的协议/票据选型未确认前，步骤 1、4、5 的受影响代码不启动。

## 批次二：权威总览与 `@我`（另批，不并入前八步）

确认 F10/F11 后，先由主 agent 固定 IM RPC/HTTP/WS 兼容字段、提及存储迁移和查询边界，保存共同提交；再分配 IM、Gateway/WS、Vue 三个执行 worktree。依次完成：IM 本人会话未读摘要、Gateway 安全显示名组合、Vue 默认总览；IM 提及校验/保存/查询、WS 兼容载荷、Vue 成员选择与 `@我` 视图；最后验证双账号、改名/重名、旧消息、离群和分页快照。若真实数据库执行计划要求新索引，先单独审查迁移。总览与 `@我` 都完成并验证后才标记 F3 完成。

## 审查点

- F09 一次性票据与旧 WS 入口的过渡方式是否接受；正式浏览器只用票据。
- F10 由 IM 管理权威摘要，不用页面遍历已加载会话冒充完整总览。
- F11 普通提及使用结构化成员 ID，旧历史不反推；首批真实聊天可先运行，第二批补齐总览和 `@我`。
- 两批均保留用户集中审查；此前后端 A73/A78 阅读语义不变。
