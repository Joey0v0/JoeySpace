# 小步迁移：通过用户 RPC 注册

新增 `POST http://127.0.0.1:8082/api/v1/user/register`。请求体与旧注册一致：

```json
{"username":"alice","password":"至少六个字符的密码","nickname":"Alice"}
```

调用链：客户端 → go-zero API → 用户 RPC → 现有 MySQL `users` 表。API 校验请求格式后转交；RPC 再校验字段、检查用户名、用 bcrypt 哈希密码，并在同一个用户服务内写入用户。`nickname` 可省略，默认使用用户名。成功返回 HTTP 200 和 `{"code":0,"msg":"success"}`，随后可调用 [新登录接口](user-login.md)。旧 `:8080` 注册仍保留，便于渐进迁移。

旧 API 的 Snowflake 节点号目前为 `1`；新用户 RPC 默认使用 `2`，可通过 `USER_SNOWFLAKE_NODE_ID` 配置。两个同时写入用户表的进程不能使用相同节点号；若以后部署多个用户 RPC 副本，每个副本也需要独立节点号。RPC 的数据库功能仍通过现有 `-profile` 参数开启。

用户名长度为 3–32 个字符，密码为 6–64 个字符且不超过 bcrypt 的 72 字节限制，昵称最多 64 个字符。重复用户名返回 HTTP 409、业务码 `20001`；无效参数返回 400；数据库或 RPC 不可用返回 503，超时返回 504。数据库的唯一约束还会处理“两个注册请求同时查到用户名可用”的情况，防止重复创建。旧注册以 HTTP 200 携带业务错误码，新入口使用相应 HTTP 状态。

已执行 `go test ./api ./rpc/user`：覆盖输入校验、默认昵称、密码哈希、重复用户名、并发唯一键冲突、数据库读写失败，并通过本地 gRPC 请求验证注册方法。数据库由 SQL 测试替身提供；真实 MySQL 写入和云端容器联调留到用户统一同步后验证。
